# Backups and file storage

This section states where work files belong, how they are backed up, and how a deleted file is recovered.

## Where files belong

Work files live on the shared drive. Files kept only on a laptop are outside the backup scope, and their loss is not recoverable by the company.

The shared drive is organised by department, then by project. A project folder is created by the project's owner and carries the project code in its name, so that the folder can be matched to the purchasing and time records.

Personal folders exist for drafts. Anything another person needs in order to continue the work is moved out of a personal folder before the end of the day it was created.

## Backup schedule

The shared drive is backed up nightly, starting at 01:00. A full backup runs weekly on Sunday, and incremental backups run on the other six nights.

Backups are retained on the following schedule.

| Backup type | Retention |
|---|---|
| Nightly incremental | 30 days |
| Weekly full | 12 weeks |
| Monthly full | 24 months |

One copy of each monthly full backup is held off site. Off-site copies are verified quarterly by restoring a sample folder and comparing it against the source.

## Recovering a file

A file deleted from the shared drive stays in the recycle area for 14 days and can be restored by its owner without help.

Beyond 14 days, recovery is a request to the systems team, stating the full path, the approximate deletion date and the reason. Requests are answered within two working days. Recovery from an off-site copy takes up to five working days and is used when the file is older than the on-site retention.

## What is never stored on the shared drive

Credentials, private keys and customer payment details are never stored on the shared drive, including inside documents and spreadsheets. Credentials belong in the password manager. A credential found on the shared drive is treated as exposed and is rotated.
